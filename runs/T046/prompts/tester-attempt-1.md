# ROLE

# Role — Tester

## Mission

Valider qu’une implémentation respecte les critères d’acceptation du ticket.

## Tu dois

- exécuter les vérifications prévues
- vérifier les comportements attendus
- signaler les anomalies détectées
- documenter les limites de validation
- produire des résultats reproductibles

## Tu ne dois pas

- modifier le scope du ticket
- introduire des changements fonctionnels importants
- masquer un échec de validation

## Sortie attendue

- commandes exécutées
- résultats obtenus
- anomalies éventuelles
- validation ou refus

## Règles

- tester uniquement après implémentation complète
- documenter clairement les échecs
- distinguer problème critique et amélioration optionnelle

Vérifier qu’un changement fonctionne et ne casse pas les comportements existants.

## Règles

- tester le comportement attendu

# SKILL: debugging

# Skill — Debugging

## Objectif

Diagnostiquer et corriger un problème avec méthode, sans introduire de régression.

## Règles

- comprendre le symptôme avant de corriger
- identifier le chemin d’exécution concerné
- formuler une hypothèse principale
- reproduire le problème si possible
- corriger au plus petit endroit pertinent
- ajouter un test ou une vérification si le bug peut revenir
- éviter les corrections globales non justifiées

## Refuser si

- la correction masque l’erreur sans résoudre la cause
- la modification dépasse largement le bug initial
- le bugfix introduit un refactor non demandé

# T046 — Replace the dark interface with a modern light visual theme

**Source**: GitHub Issue #91

## Description

## Context
The current Timizer-like interface uses a predominantly black background that feels too dark and visually heavy. The application should look like a modern professional SaaS product rather than a developer-oriented dark dashboard.

## Goal
Introduce a bright, modern, business-oriented visual theme across the whole application.

## Description
Replace the current dark global background with a light neutral page background, white or lightly tinted content surfaces, subtle borders, restrained shadows, and a professional accent colour. Review all text, cards, controls, dialogs, navigation elements, tables, and calendar states so they remain readable and visually coherent.

The result should feel contemporary, calm, spacious, and suitable for producing and signing monthly CRA documents. Avoid excessive gradients, neon colours, pure black surfaces, and overly decorative effects.

## Out of Scope
- Changing CRA business rules.
- Rebuilding backend APIs.
- Adding a user-selectable dark mode.

## Acceptance Criteria
- [ ] The default application background is light rather than black.
- [ ] Main content surfaces use a coherent hierarchy of light backgrounds.
- [ ] Text contrast remains accessible.
- [ ] Borders and shadows are subtle and consistent.
- [ ] Buttons, inputs, dialogs, cards, tables, and calendar states follow the new theme.
- [ ] No component retains an accidental dark-theme style.
- [ ] Desktop and mobile screenshots demonstrate a coherent professional visual identity.
